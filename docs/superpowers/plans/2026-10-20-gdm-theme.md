# NothingOS GDM Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Neither execution skill is installed in the current skill roots; resolve this at the execution handoff before implementation.

**Goal:** Apply the desktop wallpaper, white JetBrains Mono text and NothingOS charcoal/mint controls to GDM, with tested rollback, then push the implementation to the user's fork.

**Architecture:** Prepare the bundle as the desktop user by detecting wallpaper and extracting the installed native light/dark CSS. A privileged transaction deploys only the owned resource-overlay directory and the GDM-instance systemd drop-in. The normal user Shell, packaged resources and authentication configuration remain untouched.

**Tech Stack:** Python 3 standard library, GJS/Gio/St, fontconfig, systemd user units, PolicyKit `pkexec`, unittest and Git/GitHub CLI.

**Spec:** [2026-10-20-gdm-theme-design.md](../specs/2026-10-20-gdm-theme-design.md)

## Global Constraints

- Initially support the verified GNOME 51 layout only.
- Use the current desktop wallpaper, JetBrains Mono, and white text.
- Preserve red error/critical states and readable disabled controls.
- Do not override the native high-contrast stylesheet.
- Do not modify the packaged gresource, GNOME JavaScript, PAM, auto-login, passwords, accounts, keyrings, notification privacy or authentication settings.
- Do not install or enable another desktop extension for GDM.
- Do not restart GDM, log out the desktop, or reboot automatically.
- Keep personal wallpaper bytes, root backups and runtime data out of Git.

## Review Focus

- Wallpaper paths containing spaces/Unicode or a missing dark image: use URI decoding and select only an existing local image; fail clearly when the selected image cannot be read (Task 1).
- A matching font installed only inside the desktop user's home: reject it because GDM cannot rely on that home being accessible (Task 1).
- A symlink or another tool's deployment directory/drop-in: reject conflicts before writing, rather than following links or overwriting unrelated configuration (Task 2).
- A failure after one destination has been changed: restore both destinations and preserve the original absent/present state (Task 2).
- A GNOME update or a resource bundle changed since preparation: refuse the stale prepared bundle and require fresh preparation (Task 2).

## Files and interfaces

- `gdm-theme/login.css`: scoped visual rules and the managed wallpaper URL.
- `gdm-theme/native-theme.js`: fixed-resource extraction and St validation helper.
- `gdm-theme/theme.py`: preparation, payload validation, installation and restore functions.
- `gdm-theme/nothingos-gdm.py`: user/privileged CLI and authentication handoff.
- `gdm-theme/README.md`: activation, rollback, limitations and upgrade instructions.
- `tests/test_gdm_theme.py`: preparation and transaction tests in temporary roots.
- `README.md`: link to the new GDM component.

`theme.py` exports `select_wallpaper(settings: dict[str, str], override: Path | None) -> Path`, `prepare(output: Path, wallpaper: Path | None = None) -> Path`, `install(bundle: Path, *, root: Path = Path('/')) -> Path`, and `restore(backup: Path, *, root: Path = Path('/')) -> None`. The `root` argument is a test seam; the production CLI never accepts an arbitrary install root.

Prepared bundles contain only `gnome-shell-light.css`, `gnome-shell-dark.css`, `wallpaper.<validated-extension>` and `manifest.json`. The manifest records their hashes, the installed resource hash, Shell version and the exact GDM service instance. Native stylesheet extraction uses Gio directly; no package resource is rebuilt or replaced.
